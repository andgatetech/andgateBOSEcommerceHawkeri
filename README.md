# AndgateBOS Ecommerce Storefront

Public-facing ecommerce storefront for AndgateBOS merchants. Built for end-customer shopping, guest and authenticated checkout, order tracking, and PWA installability.

## Stack

- Next.js 16.2.2 / React 19.2.4
- TypeScript (see package-lock.json)
- Tailwind CSS 4.2.2
- Redux Toolkit 2.11.2 + RTK Query
- Zod v4 for validation
- `jspdf` + `jspdf-autotable` for invoices
- Turbopack for development; webpack for production builds

## Quick Start

```bash
cd andgateBOSEcommerceHawkeri
npm install
cp .env.example .env
npm run dev
```

Default local URL: http://localhost:3001

## Architecture

- **Server data fetching:** `serverFetch.ts` wraps native `fetch` for RSC pages with configurable cache/revalidate.
- **Client data fetching:** RTK Query with bearer token injection, auto-logout on 401, retry middleware.
- **Auth:** Three-layer — `authStorage.ts` (localStorage) → `AuthHydrator.tsx` → `ProtectedLayoutClient.tsx` route guard.
- **Cart:** Dual-cart system. Guest cart is a Redux slice backed by localStorage; authenticated cart syncs with the server. `GuestCartMerger.tsx` merges guest items on login.
- **Checkout:** `CheckoutMode = "gate" | "guest" | "auth"`. Guest checkout creates an ephemeral `EcommerceUser` from phone.
- **PWA:** Custom service worker with CacheFirst static, StaleWhileRevalidate images, NetworkFirst API. Manifest generated by Next.js.

## Known Risks

- Bearer token stored in `localStorage` (XSS risk). Migration to httpOnly cookie requires backend change.
- No route-level `error.tsx` boundaries.
- `CheckoutView.tsx` is large and a known decomposition target.
- Shipping fee is client-side only; backend must re-validate on order creation.
